## Found on real device (XOGOT), fixed in code

| ~~K-14~~ | **CLOSED** | **All 149 textures imported as Lossless RGBA8 with no mipmaps** — 144.1 MB of VRAM, 112.8 MB of it the 96 world textures. Two causes: `compress/mode=0` is Godot's *2D* default while its own 3D preset defaults to 2, and the automatic `detect_3d` upgrade can only fire when the editor sees a texture in a 3D material — this project builds every material procedurally at runtime, so **zero** `.tres`/`.tscn` files reference any texture and detection never ran. Invisible on desktop (ample VRAM, shimmer easy to miss); on iPhone it is the dominant texture memory cost plus aliasing on every repeating surface and poor texture-cache locality | Fixed at wave 49: VRAM Compressed + mipmaps on all 96 world textures, `compress/normal_map=1` on the 23 normal maps, `roughness/mode=6` + `roughness/src_normal` on the 18 roughness maps. **144.1 MB → 12.0 MB.** Harness step 98 asserts the params from the `.import` files so they cannot silently revert. D-25 |
| ~~K-15~~ | **CLOSED** | **XOGOT's iOS Virtual Controller could draw a second control layer on top of the game's own touch interface**, with both firing the same Input Map actions. `project.godot` had no `input_devices/virtual_controller/*` key at all, leaving it to whatever the device default is | Fixed at wave 49: `input_devices/virtual_controller/enable=false` written into `project.godot` so it travels with the repo. Xogot's `Onscreen Controls.md` instructs exactly this when a project ships its own complete in-scene interface. Verified Xogot-specific, not Godot: zero hits for `virtual_controller` in Godot 4.7.2 `core/config/project_settings.cpp`. D-26 |
| ~~K-16~~ | **CLOSED** | **`project.godot`'s own header instructed a false constraint**: "API surface restricted to Godot 4.5-stable-documented features for XOGOT compatibility." XOGOT's App Store runtime has been Godot **4.7** since release 1.7.2. The error came from reading the age of the Godot manual *bundled with XogotDocs* (a 4.5-era snapshot) as the version of the *engine* | Fixed at wave 49: header rewritten to state the 4.7 API surface, the XOGOT 1.7.2 version floor, and the doc/engine split explicitly. D-02, D-02a, D-27 |
| ~~K-17~~ | **CLOSED** | **VRAM compression was enabled for the world textures (D-25) without enabling the formats that make it usable.** `rendering/textures/vram_compression/import_etc2_astc` and `import_s3tc_bptc` were both absent from `project.godot`, and both default to `false` in the engine. The importer then falls back to the *host* OS preference — ARM → ETC2/ASTC, x86 → S3TC/BPTC — so each machine imports only its own format. A project imported on a desktop or on Xogot for Mac and run on an iPhone would have had **no texture data the iPhone GPU can read**: `Texture (binding: 0, index 0) is not a valid texture. / Failed to create uniform set for batch.` It also meant the x86 sandbox harness could never exercise the ASTC path the device actually uses | Fixed: both flags set `true` in `project.godot`; harness step 98 asserts both. Exactly the fix Xogot's own `faq.md` prescribes. D-28 |
| ~~K-18~~ | **CLOSED** | **`display/window/stretch/scale_mode` was unset**, so the project inherited Xogot's new **"Auto"** default, which its `faq.md` says "can cause the game to appear zoomed in or stretched" in projects "not designed with high-DPI in mind" | Fixed: set to `"fractional"` (which is also Godot's own default, so nothing changes on desktop) and asserted by harness step 98. D-29 |
| ~~K-20~~ | **CLOSED** | **No save when iOS takes the app away.** Every autosave trigger was a discrete achievement (mission complete, safehouse rest, hidden stash, property purchase, manual save). iOS terminates backgrounded apps routinely under memory pressure, so a player interrupted mid-mission could lose everything since the last job they finished | Fixed: `game.gd::_notification()` autosaves on `NOTIFICATION_APPLICATION_PAUSED`, raised by `OS_AppleEmbedded::on_enter_background()` before audio and rendering are torn down. Deliberately not FOCUS_OUT, which also fires for transient interruptions. Harness step 98 asserts both halves. **No pause handler added** — the engine already halts the frame loop (invalidates the `CADisplayLink`), stops the audio driver, releases sticky `action_press` state and clears touches; duplicating that would be cargo-cult. D-30 |

Third instance of this class after the missing `music_finale` and the silent fuel pumps, so step 98 now cross-references **every** literal `sfx()`/`sfx_at()`/`play_music()`/`sting()` name in the codebase against the files on disk, plus every voiced character's `_0/_1/_2` vox bank |
