| D-25 | **World textures import VRAM-compressed with mipmaps** (`compress/mode=2`, `mipmaps/generate=true`), normal maps flagged `compress/normal_map=1`, roughness maps `roughness/mode=6` (Gray) with `roughness/src_normal` wired to their pair, and `detect_3d/compress_to=0` | All 96 world textures shipped as **Lossless RGBA8 with no mipmaps** — 112.8 MB of VRAM for the world set alone, 144.1 MB across all 149. Two causes, both invisible on desktop: (1) `compress/mode=0` is Godot's *2D* default, and Godot's own **3D preset defaults it to 2** (`resource_importer_texture.cpp:232`, `p_preset == PRESET_3D ? 2 : 0`); (2) the automatic `detect_3d` upgrade can only fire when the *editor* sees a texture used by a 3D material in a scene or resource — and this project builds **every** material procedurally at runtime via `load()` in `world_gen.gd::mat()`, so **zero** `.tres`/`.tscn` files reference any texture and detection never runs. No mipmaps also means shimmering aliasing on every repeating asphalt/concrete surface and poor texture-cache locality on a mobile GPU. VRAM-compressed + mipmaps: **112.8 MB → 9.4 MB** for the world set (144.1 → 12.0 MB overall). UI and face textures deliberately stay Lossless: they are 2D, they are mostly smooth gradients where block compression bands, and they are not all resident at once | Enum values read from `editor/import/resource_importer_texture.{h,cpp}` in the 4.7.2 tree: `compress/mode` "Lossless,Lossy,VRAM Compressed,VRAM Uncompressed,Basis Universal"; `compress/normal_map` "Detect,Enable,Disabled"; `roughness/mode` "Detect,Disabled,Red,Green,Blue,Alpha,Gray"; `detect_3d/compress_to` "Disabled,VRAM Compressed,Basis Universal". Roughness maps verified grayscale by decoding all 18 PNGs (max inter-channel diff 0). Harness step 98 asserts the params from the `.import` files |

| D-28 | **`rendering/textures/vram_compression/import_etc2_astc=true` AND `import_s3tc_bptc=true`** in `project.godot` | D-25 is not safe without this. Both keys default to **`false`** (`servers/rendering/rendering_server.cpp:3659-3660`, `GLOBAL_DEF_RST` — restart-required). `ResourceImporterTextureSettings::should_import_etc2_astc()` returns true only if the setting is on **or the host OS prefers that format** (`core/os/os.cpp:749`: `return PREFERRED_TEXTURE_FORMAT_ETC2_ASTC; // By rule, ARM hardware uses ETC texture compression`, while x86 returns S3TC_BPTC). With both off, each machine imports **only its own format**, so a project imported on a desktop — or on Xogot for Mac — and then run on an iPhone contains no texture data the iPhone GPU can read. That is verbatim the failure Xogot's `faq.md` documents: *"Texture (binding: 0, index 0) is not a valid texture. / Failed to create uniform set for batch." → "you need to enable importing S3TC BPTC and ETC2 ASTC … Then close and reopen the project so that these imports will run."* Xogot advertises exactly the cross-device workflows that trigger it ("Start a game on iPad and continue on your desktop"; Remote Debugging edits on one device and runs on another). Second, independent reason: **this project is verified on x86 Linux**, so with `import_etc2_astc` off the sandbox import never produces the ASTC data the device actually uses and any ASTC-only defect is invisible to the harness. Runtime cost is nil — Godot uploads only the format the GPU supports; the extra format lives in the `.godot/` import cache, which is gitignored and regenerated per device | `editor/import/resource_importer_texture_settings.cpp:38-54`; `editor/import/resource_importer_texture.cpp:888-900` (`formats_imported` is populated only from these two flags — if neither is on, no usable ctex is written); `servers/rendering/rendering_server.cpp:3659-3662`; XogotDocs `faq.md`. Harness step 98 asserts both |

| D-30 | **Autosave on `MainLoop.NOTIFICATION_APPLICATION_PAUSED`** in `game.gd::_notification()`, and deliberately *not* on FOCUS_OUT | iOS terminates backgrounded apps under memory pressure, and every existing autosave trigger was a discrete achievement (mission complete, safehouse rest, hidden stash, property purchase, manual save) — so an interruption mid-mission could lose everything since the last finished job. PAUSED is the "we may be terminated" signal and `OS_AppleEmbedded::on_enter_background()` raises it *before* calling `on_focus_out()`, so audio and rendering are still alive and the write completes. FOCUS_OUT is rejected because it also fires for transient interruptions (notification banner, Control Center) where the app is not at risk. **No pause handler was added**, because the engine already does that job and duplicating it would be cargo-cult: `stopRendering` invalidates the `CADisplayLink` driving `drawView`, so the frame loop halts entirely and no mission timer ticks blind; `audio_driver.stop()` silences audio; `Input::release_pressed_events()` walks `action_states` and releases anything `cache.pressed`, including the sticky state `Input.action_press()` creates — which is exactly what this project's touch buttons use; and the view calls `clearTouches` | `drivers/apple_embedded/os_apple_embedded.mm:774-825` (`on_focus_out`, `on_focus_in`, `on_enter_background`); `drivers/apple_embedded/godot_view_apple_embedded.mm:175-213` (`stopRendering` invalidates the display link); `scene/main/scene_tree.cpp:912-950` (PAUSED and FOCUS_* propagated to nodes via `get_root()->propagate_notification`); `core/input/input.cpp:1600-1623` (`release_pressed_events`). Harness step 98 asserts both halves: FOCUS_OUT writes nothing, PAUSED writes a real payload |
| D-31 | **Assert the `.ctex` header, not `Texture2D.has_mipmaps()`** | The obvious API is a trap: the base `Texture2D::has_mipmaps()` only calls the `_has_mipmaps` *GDScript virtual* and returns its out-param, and `CompressedTexture2D` does **not** override it — only the `3D` and `Layered` variants do. So it returns `false` for a correctly-mipped VRAM texture and the first version of this assertion failed while the artefacts were right. Step 98 instead opens the file the `[remap]` block points at and reads the header: magic `GST2`, uint32 version/width/height/data-format, where `FORMAT_BIT_HAS_MIPMAPS` is `1 << 23` and the low byte is the `DataFormat` enum (`0` = `DATA_FORMAT_IMAGE`, raw VRAM blocks; `1`/`2` = PNG/WEBP lossless). It asserts **both** `path.s3tc` and `path.etc2`, because the ETC2 artefact is the one an iPhone uploads and an x86-only import would never have produced it. Verified: 96×2 artefacts, all mipmapped, all `DATA_FORMAT_IMAGE`; `asphalt.png` 512² went 1,048,576 → 174,828 bytes (4 bpp × 4/3 mip chain) and `asphalt_n.png` is correctly 2× that at BC5 8 bpp | `scene/resources/texture.cpp:55-59` (base `has_mipmaps` is virtual-only); `scene/resources/compressed_texture.h` (`CompressedTexture2D` has no `has_mipmaps` override; `FORMAT_BIT_HAS_MIPMAPS = 1 << 23`, `DataFormat` enum); `scene/resources/compressed_texture.cpp:44-67` (header read order) |
